## 1. The project

**SAGA (Spatially-Aware Gated Attention)** adds one small learned gate per transformer block to a ViT: `phi`, an `nn.Parameter` of shape `[num_heads, n_patches]` at state key `blocks.{i}.attn.gate.phi`; `sigmoid(phi)` multiplies the patch-token SDPA outputs (CLS is never gated). The research question: do ViT pathologies — attention sinks (a few patch tokens with enormous norms), oversmoothing, collapsing effective rank — shrink under a learned SPATIAL gate, and does that buy accuracy, compared against (a) an ungated baseline and (b) trained register tokens?

The project was salvaged and re-run from a legacy codebase whose results could not be trusted. Everything below therefore rests on re-derived or newly trained runs with verified provenance (checkpoint sha256 in every results JSON), and a set of legacy results is formally VOID (section 3).

## 2. How to read every number in this repo

- **Numbers are sacred.** Every experimental number comes from a file under `results/`; gaps are `MISSING`, never estimated. Notes and tables are GENERATED by scripts in `analysis/` — tests re-render them and require byte-identity, so hand-typed numbers cannot survive.
- **Cell identity = `recipe_actual`**, resolved from the run's RESOLVED training config, never a directory name. The legacy `load_config` silently dropped `variants_nomix.yaml`'s augmentation block, so **every legacy e2 run — including all `*_nomix` directories — trained WITH MixUp+CutMix (0.8/1.0)**. Proof: `results/notes/recipe_erratum.md` (resolved-config diff = zero keys); the ViT-B trio was settled by an HPC config harvest (`results/legacy/resolved_configs/`). The only mixup-free (true-nomix) classification runs in the project are the four e2r ViT-S runs trained after the two-key intervention (mixup_alpha/cutmix_alpha → 0, criterion → LabelSmoothingCE).
- **Sink metric generations.** v1 (per-arch tau, saturated on ViT-B/mixup) and v2 (per arch|dirname-recipe, frozen as TASK-02C provenance, never applied to e2r run dirs) are historical. The PRIMARY metric is **canon**: per `(arch, recipe_actual)` fixed tau calibrated on the cell's seeded s1 baseline (`results/diagsplit/fixed_thresholds_canon.json`): `vit_small|mixup` = 20.8515625, `vit_base|mixup` = 127.3125, `vit_small|nomix` = 22.859375. `sink_mad_k5` (per-image median+5·MAD) is reported beside it but tracks the norm bulk, so it is confounded exactly where a gate compresses norms (PROJECT.md §3.2).
- **Statistics discipline.** Repeats are listed individually before any mean; sample std (n−1); SE = sd/√n; `significant_2xSE` means |mean| > 2·SE; Welch is an unpaired robustness line; MISSING is never averaged; n=2 SEs are stated but flagged unreliable. Paired deltas pair by provenance tag / ft-seed / image — never across architectures or datasets.
- **Exact eval is fp32** (`tools/eval.py`, `amp: off`); the trainers validate under bf16. The two differ by ±0.03–0.04 top-1 (~15–20 images of 50 000) — eval JSONs are the paper numbers, log.csv values are labelled bf16 wherever both appear.

### 5.4 The sink address (TASK-07; `results/tables/sink_address.csv`, canon basis, exact spatial permutation nulls)

1. **Sinks have a spatial address, and it is a border RING** one patch inside the edge for every mixup-trained member (S/mixup baseline s1: ring-1 freq 0.1629 vs ring-0 0.0740), and FLAT for true-nomix (ring-1 0.0189). The address is created by the mixup recipe.
2. **Seed-stable**: baseline-pair Spearman 0.912 (S/mixup, n=6 pairs spanning legacy AND seeded reruns), 0.851 (B/mixup), 0.711 (S/nomix) — 8/8 pairs p<0.05 under the exact spatial null.
3. **NOT recipe-stable**: cross-recipe mean 0.305 canon / 0.134 mad — largely inside the spatial null.
4. **SAGA consolidates the address; registers relocate it.** SAGA-vs-baseline map correlation 0.873 (S/mixup) while total sink mass falls (-8.08); registers land at 0.477 (S/mixup) and 0.006 (B/mixup, p 0.95) — a different mechanism. Caveat from the note: the B/mixup registers map itself is Monte-Carlo-noise dominated (almost no sinks left to place), so that one value is not comparable with the other cells (`sink_address.md`).
5. **The gate tracks the address negatively in ViT-S/mixup only**, peaking at layers 7-8 with all four repeats Bonferroni-significant — the gate is suppressed exactly on the border ring where sinks form. Not significant on B/mixup; signs disagree on S/nomix. (Per-layer values in `sink_address.csv` Q5 rows; figure `results/figures/Faddr_draft.pdf`.)

### 5.7 Ring ablation (TASK-13; eval-only pixel masking on the 24 fine-tuned checkpoints; `results/tables/T_ring_ablation.csv`)

## 7. What was built and fixed to make the numbers trustworthy

**Bugs found and fixed (each VOIDs or corrects a number class):** B1 inexact eval → exact fp32 full-val with sharded all_reduce; B2 prefix-token inference; B3 oversmoothing closed form; B4 mIoU ignore-pixel structure; B5 detection double normalization; B6 registers backbone dropping `reg_token` under `strict=False`; B7 fine-grained test-split selection; the COCO label-space mismatch; the resized-frame box-scoring bug (an oracle detector scored AP 0.0 — every pre-fix detection number was meaningless); the TASK-06B gate-pooling precedence bug; the TASK-07 finite-sample concentration floor (two published-sign inversions caught).
**The recipe-identity correction** (TASK-06B): `recipe_actual` doctrine, erratum note, manifest column, canon thresholds.
**Infrastructure:** a legacy-math-identical seeded trainer with atomic per-epoch checkpoints, `--resume auto`, append-safe logs and schedule-geometry guards; idempotent derivation drivers with sha-keyed skip guards and completion gates; the dense trainers rewritten with the same hygiene (rank-0 broadcast decisions, trap-released scratch staging, transactional best-artifact sets); the TTR harness with frozen gate criteria and paired-bootstrap CIs; a frozen probe set and attention-dump tooling; the matched-init gate-mode family. Everything that produces a paper number records seed, git sha and checkpoint sha256.
**Process:** every substantive task ran adversarial review workflows; they found real, number-changing defects in nearly every task (the box-frame bug, the gate-pooling bug, the sign-inverting Gini floor, the set -u/module failures). The test suite grew from 31 to 600+ (CPU, fake data).
